Document Workflow

Phase 5 Priority 1/2: the shared queue every document type (Journal Voucher, Customer Invoice, Supplier Bill, etc.) passes through — Draft → Submit → Approve/Reject → Post. A user cannot approve or post a document they created unless acting as CEO/Admin (a logged override).

Trial Balance

Project Ledger

Cost Centre Report

Customer Invoice

Phase 5 Priority 3 (AR). A smart form that builds AR Dr / Revenue Cr (+ Tax Cr if a tax code is chosen) and saves it as a Draft through the SAME lifecycle engine as a manual Journal Voucher — no second posting mechanism.

Customer Receipt

Phase 5 Priority 4/5 (Open Items / Clearing). Posts Bank Dr / AR Cr immediately (receipts don't need the draft workflow — they clear an already-posted, already-approved invoice) and creates an explicit clearing record. Supports partial and full clearing — enter less than the open balance for a partial.

Customer Ledger

Phase 5 Priority 9. Date / Doc Type / Doc No. / Reference / Debit / Credit / running Balance / Project / Clearing Document / Status — for one customer, derived from the same journal lines as every other report.

Accounts Receivable Ageing

Phase 5 Priority 10. Buckets: Current, 1-30, 31-60, 61-90, 91-180, 181-365, 365+, by due date. Click a customer with a balance to drill to their open items, then to the source invoice.

Supplier Invoice (Bill)

Phase 5 Priority 10 (AP mirror of AR). Builds Expense Dr (+ Input Tax Dr if applicable) / AP Cr, saved as a Draft through the same lifecycle engine.

Supplier Payment

Posts AP Dr / Bank Cr and creates an explicit clearing record against an open bill. Supports partial and full clearing.

Vendor Ledger

Accounts Payable Ageing

Mirror of AR Ageing, by vendor and due date.

Purchase Orders

A Business Document (per §4.1 pipeline) — issuing a PO does NOT post to the GL. It becomes an open commitment against the project budget until billed.

Committed Cost Report

Build item 3: a third bucket alongside Budget and Actual — the value of issued-but-not-yet-billed POs per project. Actual is GL-derived (§4), Committed is derived from open Purchase Order business documents.

Project P&L — GL-Derived

Build item 5 (highest value, sequenced last on purpose — it depends on items 1–3 above). Revenue and cost are both filtered views of the same central line-item model, not a parallel calculation engine. This is the direct fix for the "project profitability computed by re-scanning operational tables" gap identified in the Discovery report §2.5.

Financial Reconciliation

Phase 5 Priority 11. AR subledger (sum of open items) must equal the AR control account (1100) balance; AP subledger must equal the AP control account (2000) balance; GL must stay balanced throughout. Any mismatch here is a release blocker, not a cosmetic issue.

Tax Codes (Config Only)

Build item 4: config-driven CGST/SGST/IGST, replacing the live ERP's flat hardcoded 18% field. Deliberately NOT wired to auto-post — matches the live system's own disclosed caution pending accountant sign-off. Tax lines can still be added manually to a journal entry via the Tax Code column on the Post tab.

Document Types & Number Ranges

Build item 2: one table-driven scheme replacing the current live ERP's three inconsistent numbering approaches (voucher-scan, PO year-inline, Invoice free-text/random fallback). Every document type owns its own gapless sequence.
